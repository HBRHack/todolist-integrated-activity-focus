Saat ketemu bug perilaku (sorting/filter tidak jalan, view tidak sinkron, dll.),
**baca dulu source code test** — `tests/backend/tst_backend.cpp` dan
`tests/qml/tst_*.qml` meng-encode perilaku eksternal yang diharapkan
(urutan, filter, role proxy, sinkronisasi lintas view). Banyak bug selesai
dengan mencocokkan implementasi ke assertion test. Jangan ubah test demi
menyesuaikan kode tanpa alasan yang dicatat.

## The two-layer model

The engineering skills (`implement`, `tdd`, `code-review`, `diagnosing-bugs`,
`triage`, `to-spec`, `to-tickets`) carry **workflow only**. They were written
around a web/modern-stack baseline and know nothing about Qt semantics. The Qt
knowledge lives in three dedicated skills, which are the **enforced target
language rules** for this repo:

| Skill | Scope | Load when |
|---|---|---|
| `qt-515` | Qt 5.15 master rules: containers, ownership, threading, C++/QML boundary, CMake §6, field-tested gotchas (§7) | Before writing or reviewing ANY Qt/C++/QML code |
| `cpp-code-review` | Pure-C++ review (string_view lifetime, const-correctness, RAII, containers, smart pointers) — Qt parts defer ke `qt-515` | `code-review` Standards axis untuk file C++ di repo Qt |
| `cpp-standards-reference` | Sitasi standar ganda N3337 (C++11) vs N4659 (C++17), Router wajib 4 langkah | Setiap temuan C++ di `code-review` — format `[N4659 §... \| N3337 §...]` |
| `qt515-reference` | Qt 5.15.2 API docs (`html/<module>/<page>.md`) + `qml-integration-checklist.md` | Setiap temuan Qt API di `code-review` — kombinasi checklist + html penuh |
| `qt-cpp-builder` | Qt 5.15 scaffold/fix Widgets, QML integration, CMakeLists code | Build file changes, scaffold new components |

## Bridge code-review ↔ C++11/17 + Qt refs (wajib untuk semua file C++/QML)

`code-review` `## Qt rule` sekarang mewajibkan bridge ini (lihat
`~/.agents/skills/code-review/SKILL.md` `### Qt 5.15 + C++ Standards Bridge`).
Ringkasnya untuk agen pelaksana:

1. Load order: `qt-515` → `cpp-code-review` → `cpp-standards-reference` → `qt515-reference`, dalam sesi yang sama.
2. Routing cepat:
   - Bahasa inti / STL (`optional`, `variant`, `string_view`, structured
     bindings, `if constexpr`, container, `constexpr`) → `cpp-standards-reference`
     `references/index-11-vs-17.md` → `cpp11-core.md` / `cpp17-safe-in-qt515.md`.
     Fisik PDF = cetak + 14 (`pdftotext -layout -f <fisik> -l <fisik>`).
   - QObject / signals-slots / ownership / threading QThread →
     `qt-515` menang, `cpp-code-review` skip bagian itu.
   - Q_PROPERTY / model / ownership menyeberang / expose-sebelum-load →
     `qt-515 §2` + `qml-integration-checklist.md` dulu.
   - Kelas/fungsi Qt (`QObject`, `QString`, `QAbstractListModel`, `QThread`, …) →
     `qt515-reference` `index/<module>.md` → `html/<module>/<page>.md`,
     cantumkan path di laporan.
   - Tidak ketemu di index → `cppreference-fallback.md` (C++) atau source HTML
     asli / `doc.qt.io/qt-5.15/` (Qt).
3. Klaim "C++17-only" wajib bukti compiler (`g++ -std=c++11` gagal vs
   `-std=c++17` sukses) bila memungkinkan. Tanpa sitasi dua sisi, temuan
   dianggap belum lengkap — setara missing `qt-515`.
4. Verdict per file: `Verdict: C++11-clean / C++17-clean / needs C++17 (fitur: …) / breaks C++11 (baris: …)`.

   `code-review` versi lama tanpa section bridge ini walau file di disk sudah
   baru. Bila output skill tidak memuat `### Qt 5.15 + C++ Standards Bridge`,

## Rule (enforced at opencode level)

1. An issue spec under `.scratch/` that touches Qt code MUST instruct the
   implementing agent to load `qt-515` first, in the same session as the
   engineering skill.
2. Failing to load `qt-515` before Qt work is a **review blocker**.
3. `qt-515` §7 gotchas are accrued debt from this repo — check them before
   debugging anything new; add new finds there and in `docs/` too.

  **FIXED (2026-08-05):** `ItemModel`, `InboxProxyModel`, `ListProxyModel` now

## New gotchas (isu 06–09 integration tests, 2026-08-05)

- **§7.20 QML `Connections` handlers run BEFORE earlier C++ direct slots.**
  A `Connections { target: repo; function onChanged() { ... } }` fires before
  `ItemModel`'s reload (connected first, in its ctor) — verified with a probe:
  the handler read `itemModel.count === 0` while the row already existed.
  Consequence: any view that rebuilds UI *from model data* inside `onChanged`
  sees stale data for one cycle. Fix pattern (used in `ViewCalendar.qml`):
  defer the rebuild with `Qt.callLater(root.buildGrid)` so it runs the next
  event-loop turn, *after* the synchronous reload. Views that rebuild from
  DB-backed calls (`repo.boardList()` etc.) are unaffected.
- **§7.21 Do not assert `.visible` in QtQuickTest offscreen/xcb.**
  The test window's root `Item` reports `visible === false`, and Qt clamps
  `visible = true` writes on items in an invisible tree — a direct write reads
  back `false` (verified with a 5-line minimal probe; `opacity`/`text` writes
  work fine). Assert rendering/state instead (e.g. `findChild(...)!==null`,
  proxy counts), not `item.visible`.

## New gotchas (isu 09 mind-map core, 2026-08-05)

Ditambahkan ke skill `qt-515` §7.9–7.14 — salinan kanonik di
`~/.agents/qt/qt5.15/skills/` (sudah di-mirror ke `~/.opencode/skills/`).
Ringkasan cepat:

| § | Pelajaran |
|---|---|
| 7.9 | `Item` tidak punya `onWheel` di 5.15 (itu Qt 6.2+); pakai `WheelHandler`, delta baca dari `point.rotation` (±120/notch). Arah zoom (`rotation > 0`) belum terverifikasi offscreen — cek manual. |
| 7.10 | Child draggable di dalam `Flickable`: `preventStealing: true`; assignment JS memutus binding → pakai `nodeStart + delta`, jangan `x += delta`. |
| 7.11 | `MouseArea.clicked` tetap terpicu setelah drag (tanpa threshold) → guard `dragActive`. `ViewCalendar.qml` punya bug laten ini (popup detail terbuka tiap drag kartu). |
| 7.12 | `mapToItem` menembus transform → koordinat ruang lokal target (tidak ter-scale); simpan koordinat dunia. `point` QML tidak punya `isNull()` → expose `hasNodePosition` eksplisit. |
| 7.13 | `QPointF` ↔ QML `Qt.point` lintas batas langsung via `Q_INVOKABLE`, tanpa `QVariantMap`. |
| 7.14 | Reload+diff `sameItem()` membuat write data non-item (posisi node) murah — `dataChanged` tidak terpancar, delegate stabil. Seam test "restart" QML = destroy + recreate view. |

## New gotchas (isu 10 mind-map edges, 2026-08-05)

Ditambahkan ke skill `qt-515` §7.15–7.19 — salinan kanonik di
`~/.agents/qt/qt5.15/skills/` (sudah di-mirror ke `~/.opencode/skills/`).
Ringkasan cepat:

| § | Pelajaran |
|---|---|
| 7.15 | Dua gesture di satu `MouseArea` (right-drag vs left-drag): `acceptedButtons: Qt.LeftButton \| Qt.RightButton`, cabang di `onPressed` via `mouse.button`, tandai saling eksklusif; `onClicked` harus filter `mouse.button === Qt.LeftButton` karena terpicu untuk kedua tombol. |
| 7.16 | QtTest drag lintas item: setelah grab, event tetap dikirim ke grabber dengan koordinat lokalnya; item target hanya menentukan titik scene. Hit-test akhir via `mapToItem(kanvas, mouse.x, mouse.y)`. |
| 7.17 | Binding deklaratif tidak track function-call (`x: nodePosition(id)` dibaca sekali saat delegate dibuat) → untuk posisi node, set sebelum `createMap()`. Sebaliknya, edge "ikuti drag" live via referensi objek yang di-assign di `Component.onCompleted` (`childNode.x` re-track); guard null dengan ternary. |
| 7.18 | Delegate Repeater adalah anak Repeater (bukan orang tuanya) → hit-test pakai `repeater.itemAt(i)` (ada sejak Qt 5.4) + cek rect, bukan `childAt`. Z-order: declare edge `Repeater` sebelum node `Repeater`. |
| 7.19 | Rebuild daftar edge (side-table) di JS turn yang SAMA dengan `applyFilter`/`repo.changed` — kalau tidak, delegate edge masih memegang referensi node yang sudah di-destroy (binding mati). `refreshEdges()` di tempat yang sama dengan filter. |
